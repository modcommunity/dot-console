# DotConsoleKit

Four games (arena, g2gfast, playground, hungario) once built a console by hand, the same ~60 lines each, and the rest had none, so a setting-shaped command like dot-menu's `net_stat` could be typed in only four games. `DotConsoleKit.build(host, settings, menu)` is those lines once: `help`, `clear`, `settings`, every key in the settings' schema bound by name (`bind_setting`, so a new setting is a new command with nothing to add), the in-process server's console unprefixed and last, and the panel on CanvasLayer 128.

**It registers the panel as one of the menu's overlays** (duck-typed `add_overlay` / `overlay_opened`; the panel answers `is_open`, `close` and emits `closed`). An input sampler polls the keyboard, and a line edit having focus does not stop `Input.is_action_pressed`, so a console that is not an overlay walks the player forward while they type `noclip`. Every game on dot-menu already stops movement and frees the pointer on the menu's "something is open", so registering is the whole fix. A game with no `DotMenu` (game-arena) wires the console's own open and close to its sampler instead.

**`sm`, the player's own block list, is one of the local commands** (`add_self_mute(local)`, also called by `local_source`): `sm` lists who is here, `sm <number|name|#userid>` mutes or unmutes their chat and voice on this client only. The list is dot-chat's `DotChatSelfMute`, reached as the registry's `dot_self_mute` or by its script path, so this addon still names nothing outside dot-core; without dot-chat in the build there is no `sm`. It is the same list the chat box's `!sm` runs.

**Who calls it**: every game and dot-game-template, each linking `addons/dot_console`, **except game-playground, whose hand-built console is not moved onto the kit yet** (queued as `move-arena-g2gfast-1`, which has done arena, g2gfast and hungario). Suite section 9 covers the kit.
